Privacy dial

Chain decoys are offered only on regtest in this demo.

A light wallet asks an Electrum server about each of its addresses, so the server learns all of them at once. Electrum's own FAQ says the server "can now reasonably guess that all these addresses belong to the same entity".

Haystack sends each real address among decoys that look the same to the server, so the server has to guess which ones are the wallet's. Plain is a copy of the same wallet that sends only its own addresses, as every Electrum wallet does today.

After every sync, this repository's own attacker reads what the server saw and makes that guess. The scores and the grids below show how well it does.

Chain decoys. Decoys taken from the chain are found by asking this same server about random transactions. A server that reads its own log of those lookups can cross off every chain decoy, which puts the addresses with coin history back where the no-history decoys leave them. That attack is described in docs/02-design.md and not built, so the score with chain decoys holds only against a server that ignores its own log.
How the score is computed

All addresses. The attacker ranks every address it was sent and picks as many as the wallet really has. Precision is the share of those picks that really are the wallet's. The page turns it into bits, −log2(precision), capped at random guessing. 0.00 bits means every pick was right, which is what plain Electrum gives. log2(padding) means the picks were no better than random.

Example: at padding 10, a wallet with 133 addresses sends 1,330. Random picks of 133 hold 133 × 133 / 1,330 = 13.3 real ones, a precision of 10%, and −log2(0.1) = 3.32 bits.

Addresses with coin history. The same measurement, restricted to the addresses the server reports transactions for. They are the ones that have held the balance, and the first number can hide them, because unused addresses outnumber them.

The words. "Hidden" means within 0.3 bits of the best this setting allows. "Exposed" means under 0.05 bits. "Partly hidden" is everything in between.

What the attacker is assumed to know. It sees every address this wallet sends, in order, on every sync, and knows how the wallet software behaves. The score covers only the attacks in this repository: comparing syncs (T1) and, when a training set is present, a structural model trained on other wallets' sessions (T2). An attack nobody wrote does not show up in the number. Not modelled: linking addresses through shared transactions on chain, sync timing, and which transactions the client fetches.

The regtest chain

A private chain where blocks are mined on demand and coins are worthless.

A payment lands on the next unused address. An address that goes from no history to some while being watched must be real, because nobody pays a decoy, so the next sync exposes it. The wallet's own payments are broadcast through bitcoind, not the sync server, so the server can't tie them to this wallet's sessions.

Restore

To restore this wallet you need two things: the descriptor, which derives every address, and the ledger file, which records how many decoys each address was given the first time it was queried. The decoys themselves are rebuilt from the descriptor; the counts are not.
