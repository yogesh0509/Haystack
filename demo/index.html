Haystack demo wallet

Starting…

Two copies of one wallet sync against the same server. Plain sends exactly the wallet's addresses, as every Electrum wallet does today. Haystack hides them among decoys. After every sync, the repository's own attacker reads that copy's session log and tries to pick out the real addresses.

How to read the score

Precision is the share of the attacker's best guesses that really are the wallet's. The headline turns it into bits: 0.00 bits means every guess was right, which is what plain Electrum gives, and log2(padding), for example 3.32 bits at padding 10, means the guesses were no better than random.

Funded is the same precision restricted to the addresses that have transaction history. They hold the balance, and the headline can hide them, because the unused addresses outnumber them.

What the attacker is assumed to know. It sees every scripthash this wallet sends, in order, on every sync, and knows how the wallet software behaves. The score covers only the attacks in this repository: comparing syncs (T1) and, when a training set is present, a structural model trained on other wallets' sessions (T2). An attack nobody wrote does not show up in the number. Not modelled: linking addresses through shared transactions on chain, sync timing, and which transactions the client fetches.
Chain decoys. Decoys taken from the chain are found by asking this same server about random transactions. A server that reads its own log of those lookups can cross off every chain decoy, which puts the funded addresses back where the no-history decoys leave them. That attack is described in docs/02-design.md and not built, so the score with chain decoys holds only against a server that ignores its own log.

The regtest chain

A private chain where blocks are mined on demand and coins are worthless.

A payment lands on the next unused address. An address that goes from no history to some while being watched must be real, because nobody pays a decoy, so the next sync exposes it. The wallet's own payments are broadcast through bitcoind, not the sync server, so the server can't tie them to this wallet's sessions.

Restore

To restore this wallet you need two things: the descriptor, which derives every address, and the ledger file, which records how many decoys each position was given the first time it was queried. The decoys themselves are rebuilt from the descriptor; the counts are not.
